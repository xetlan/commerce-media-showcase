3 · Retention curves — exposed cohort vs control PA-only

Do users who saw Adidas placements return more often than users who didn't? The real halo question.
  • D30 retention: 38% exposed vs 24% control — exposed users return at 1.58× the rate of comparable non-exposed users.
  • Effect is largest at D7–D14 (the "consideration revisit" window): 56% vs 38% (+18 pp).
  • Control cohort built from PA matched-pair propensity: users with same ltv_bucket, device_class, first_purchase_date bucket who did NOT receive Adidas exposure in the campaign window.
  • This is the behavioral counterpart of the aggregate-volume halo measurement — measures repeat-behavior uplift per user, not just "did organic search go up".
PA mechanism: Two PA cohorts (exposed / matched-control). Retention report: % of cohort returning with any qualifying event at D1, D7, D14, D30, D60, D90. Native PA view — no external tool, no DXA equivalent.

What PA does NOT do well here — be honest

This page pushed PA to its ceiling. Below the ceiling are real gaps DXA fills.
  • No managed Frustration Score — must be computed from frustration_signal aggregations. Decent proxy, not the same number.
  • No visual Zoning heatmap renderer — engagement per zone is a table or chart, not a click-through-able pixel-overlay on the page screenshot.
  • No native hesitation / time-to-click / attractiveness metrics per zone — PA captures clicks but not the rich pre-click engagement signals DXA Zoning produces.
  • Web Performance / Core Web Vitals tracking is shallow — PA can capture slow_load as an event signal, but LCP / INP / CLS as managed metrics with conversion correlation live in DXA's Speed Lab.
  • No native scroll/attention maps — PA shows whether a user clicked, not the visual surface area they actually saw.
  • No error analysis surface — JS errors and API errors as events, yes; the impact-on-goal dollarization that DXA's Error Analysis produces, no.
